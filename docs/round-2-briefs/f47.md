# F-47 — `DedicatedServerStatus::Retired`, a state no production code can produce

Round-1 audit:

> A legal transition target from three states, with a dedicated `isRetired()`
> predicate, an exclusion in the inventory sweep, and a concurrency comment in
> `SyncDedicatedServer.php:56` reasoning about a server being "Retired between
> the sweep and the worker" — a race against a state no production code can
> produce. The only writer is a test factory
> (`database/factories/DedicatedServerFactory.php:79`). Three readers, one of
> them a race-condition argument, against zero production writers.

Traced read-only. **Confirmed, and the finding is wider than the audit states
in one respect and has one extra limb the audit does not mention.**
Re-measure everything; my trace is a starting point, not a citation.

## What is there

**The zero-writers claim holds.** `grep -rn 'DedicatedServerStatus::Retired'`
over `src`, `app`, `database` and `routes` returns the enum case itself, the
`isRetired()` predicate on the enum, the model's `isRetired()`, the state
machine, the sweep exclusion, and **the factory**. No action, no controller, no
command, no job writes it. The neighbouring actions write other states:
`DecommissionDedicatedServer:75` writes **`Maintenance`**,
`ReturnDedicatedServerToStock:43` writes `Available`,
`ReserveDedicatedServer:152` writes `Reserved`,
`RegisterDedicatedServer:62` writes `Available`.

**The audit says three source states. It is seven.** Every one of these lists
`Retired` among its legal targets in `DedicatedServerStateMachine`:
`Available`, `Reserved`, `Provisioning`, `Active`, `Reinstalling`,
`Maintenance`, `Failed`. Count it yourself — the audit's "three" is the one
figure of its that does not reproduce, and a finding about a dead state should
not carry a wrong number about how many doors lead to it.

`Retired` is terminal: `DedicatedServerStatus::Retired->value => []`, no
outward edges.

**A limb the audit does not mention.** `DedicatedServer` casts
`'retired_at' => 'immutable_datetime'` (`:105`). Nothing in `src`, `app` or
`routes` writes that column either. So the schema, the cast, the predicate, the
state and seven transition edges all exist for something no code performs.

## What the round has to decide, and it is a real decision

This is not a bug to fix; it is a question to answer, and the answer belongs to
whoever owns the product:

1. **Is retirement a capability this platform is supposed to have?** If yes,
   the defect is that it was never built, and the remedy is an action — but
   **that is new operator capability and this programme does not build those**
   without it being the finding. Say so and stop.
2. **If it is not**, the state, the cast, the column, the predicate, the sweep
   exclusion and seven transition edges are dead weight that reads as coverage,
   and the remedy is deletion plus a test that keeps it deleted.
3. **The middle answer is the likely one and is the hardest to write honestly**:
   the state is *prepared* rather than dead, in the same sense the readiness
   ladder means by `prepared`. If that is the answer, say it in the enum where
   a reader will find it, rather than leaving the reader to infer capability
   from a legal transition.

**Do not simply delete it because it is unreferenced.** Read the concurrency
comment at `SyncDedicatedServer.php:56` first — it reasons about a server being
"Retired between the sweep and the worker", which is a race against a state
nothing produces. Either that comment is describing a future the codebase
intends, or it is a sentence written from the enum rather than from the
behaviour. Which of those it is decides the whole finding, and it is knowable
by reading the sweep.
