# F-30 — Horizon has no `Horizon::auth()`; 22 routes gated only by `APP_ENV=local`

**Audit text** (`docs/final-independent-multi-agent-audit-round-1.md`, Medium
block): *"`F-30` Horizon has no `Horizon::auth()`; 22 routes gated only by
`APP_ENV=local`."* — SECURITY.

Traced read-only on `claude/relaxed-turing-nh8ybf` at `d822de0`.

## The claim holds, including its number

- `grep -rn "Horizon::" app src config` returns **nothing**. `Horizon::auth()`
  is never called; `Laravel\Horizon\Horizon::$authUsing` is never set.
- `bootstrap/providers.php` registers fourteen providers and **no**
  `HorizonServiceProvider` of the application's own. Laravel's package
  discovery registers the vendor one, so Horizon is live with its defaults.
- `vendor/laravel/horizon/src/Http/Controllers/Controller.php:17` applies
  `Authenticate::class` to every Horizon controller, and that middleware
  (`Http/Middleware/Authenticate.php`) calls `Horizon::check($request)`.
- `vendor/laravel/horizon/src/Horizon.php:81-86` — with `$authUsing` unset, the
  check is:

  ```php
  return (static::$authUsing ?: function () {
      return app()->environment('local');
  })($request);
  ```

- `vendor/laravel/horizon/routes/web.php` defines exactly **22** routes
  (18 `get`, 3 `post`, 1 `delete`). The audit's count is right. Re-derive it
  anyway — a naive `grep -c "Route::"` returns 23, and that one extra is how a
  wrong number gets published.

So: the entire gate on the queue dashboard is the string equality
`APP_ENV === 'local'`.

## What I checked that the audit does not say, and which changes the round

**`config/horizon.php:40` is `'middleware' => ['web']`, and that is the package
default** (`vendor/laravel/horizon/config/horizon.php:86`), not a weakening. I
had formed the hypothesis that somebody had stripped `Authenticate::class` out
of the published config, and it is false — Horizon applies that middleware from
the controller base class regardless of config. Do not write a round on the
premise that the config was tampered with.

**It fails closed, not open.** In production `app()->environment('local')` is
false, so all 22 routes return 403. This is not a live exposure; it is an
*undeclared* control. Two consequences, and the second is the real finding:

1. **Staging and any other non-local environment is locked out too.** The
   platform's own `config/horizon.php:36` namespaces the queue prefix by
   `APP_ENV` precisely so a staging Horizon and a production Horizon can
   coexist — the configuration anticipates non-local environments that the
   authorization does not. The pressure this creates is the hazard: an operator
   who cannot see staging queues fixes it under time pressure, and the two easy
   fixes (`HORIZON_PATH` obscurity, or an `auth()` closure returning `true`)
   are both worse than what is there now.
2. **It is the only operator surface in this codebase gated by environment name
   rather than by capability.** Every other one goes through the authorization
   system (`dedicated.manage` and its siblings). Horizon is the exception, and
   nothing records that it is an exception on purpose.

**The interlock with the audit's own headline.** The audit names, separately, a
single miscapitalised `APP_ENV=Production` defeating every production guard at
once because the guards are exact string comparisons. `environment('local')` is
the same instrument pointed the other way. A round that fixes F-30 by adding an
`APP_ENV`-aware closure has reproduced the class rather than left it.

## What closing this requires

The fix is small; getting it *right* is a decision, and the round should state
it rather than assume it:

- A `Horizon::auth()` callback that consults the platform's own authorization
  (an operator capability), registered somewhere `bootstrap/providers.php`
  actually loads. Not an `APP_ENV` test in a different costume.
- A test that a non-operator authenticated user gets 403 and an operator with
  the capability gets 200, on at least one of the 22 routes — and one asserting
  the callback is registered at all, because the defect being fixed is
  *absence*, and absence comes back silently.
- Decide, and write down, what staging gets. "It is 403 in staging" is an
  acceptable answer; it is not an acceptable accident.
- `REAL_INFRA_VERIFIED = NONE`: no Horizon dashboard has ever been served by
  this platform in an environment that matters. Nothing here may change that.
