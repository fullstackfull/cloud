# F-34 brief — traced 2026-09-24, ready to dispatch

**Finding (audit, verbatim):** "Timeout quarantines can never be cleared; `ReleaseReason::OperatorAction` has no callers."

## What I confirmed by reading (main checkout, read-only)

- `ReleaseReason::requiresOperatorClearance()` returns true for `ProvisioningTimedOut` alone.
- `ReleaseQuarantinedAddresses::execute()` excludes exactly those reasons from the sweep
  (`whereNull('quarantine_reason')->orWhereNotIn(..., requiringOperatorClearance())`), deliberately and with a
  docblock explaining why a clock answers nothing.
- **Writers of `ReleaseReason` in production code, complete list:**
  `IpamReservationReleaser.php:39` JobFailed, `:57` ProvisioningTimedOut; `DestroyVpsHandler.php:204`
  ServiceTerminated; `IpAllocator.php:228` Committed; `ReapExpiredReservations.php:117` JobFailed.
  **`OperatorAction`, `CustomerRequest`, `Migration` have no production writers at all** — the audit names
  only `OperatorAction`; the other two are worth counting before the round claims a number.
- **No operator surface exists.** `routes/v1/ipam.php` is customer-only and its own docblock says there is no
  quarantine list, no history, no allocate and no release. `routes/api_admin.php` has ip-pools and subnets
  (`Permission::IpamView` / `Permission::IpamManage`) and **nothing that names an address**. No artisan command
  clears one: `ReclaimAddresses` calls `ReleaseQuarantinedAddresses`, which is the sweep that skips these rows.

So a timed-out address is withdrawn from a finite pool permanently, by design, with the exit the design names
not built. `ReportIpCapacity` counts `$subnet->quarantined`, so the leak is observable but not actionable.

## The contract is settled by the repository — do not escalate

`ReleaseReason::requiresOperatorClearance()`'s docblock states it: *"Clearing it is an operator's act: they look
at the provider, and then either the resource is adopted (the address stays with the machine) or it demonstrably
does not exist (the address is released by hand, as OperatorAction)."* **Two outcomes, not one.** A clearance
path that only releases implements half of what the file already promises.

## Scope notes for the brief

- Permissions already exist: `IpamView` to see the quarantine list, `IpamManage` to act on one.
- Operator needs to *find* the rows before clearing them, so a list surface is part of the finding, not a
  widening — "can never be cleared" includes "cannot be found".
- **Do not touch `tests/Feature/Ipam/QuarantineLifecycleTest.php`** — F-44 owns that file. New tests in a new file.
- Quantifier to re-measure rather than inherit: the audit says `OperatorAction` has no callers; the round should
  report the full census of unwritten cases and say which of them are in scope.
